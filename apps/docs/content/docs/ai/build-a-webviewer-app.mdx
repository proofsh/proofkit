After ProofKit is connected and your agent understands the file, switch from exploration to building. The goal is a local web project that previews in the browser and can later be deployed into FileMaker.

## Build loop

<Steps>
  <Step>
    **Ask the agent to scaffold a WebViewer project.**

    The project should use the ProofKit CLI and the current ProofKit stack: React, TypeScript, Vite, Tailwind, shadcn/ui, TanStack Query, and TypeGen.
  </Step>

  <Step>
    **Run the local preview.**

    The agent should start the dev server and open the app in a browser so it can inspect the result.

    <Callout title="TODO: Screenshot - Local preview">
      Capture the generated WebViewer app running locally in a browser with FileMaker-backed data visible.
    </Callout>
  </Step>

  <Step>
    **Ask for a specific screen.**

    Start with one workflow: a dashboard, detail view, calendar, kanban board, rich form, or data grid.
  </Step>

  <Step>
    **Let the agent iterate.**

    The useful loop is not just code generation. The agent should typecheck, run lint/build commands, inspect browser errors, and fix issues.
  </Step>
</Steps>

## Prompt shape

```text
Build a ProofKit WebViewer screen for the Contacts workflow.
Use the FileMaker layouts and fields you discovered earlier.
Start with a read-only list and detail view, then run checks and preview it in the browser.
```

## Style and theme

ProofKit projects use shadcn/ui and Tailwind, so the agent can apply a theme or preset by editing normal project files.
